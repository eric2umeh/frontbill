FrontBill — Roles & Permissions Reference
=========================================
Source of truth: lib/permissions.ts

Use this when editing profiles.role in Supabase (SQL Editor or Table Editor).
The app reads profiles.role and maps it to a canonical role key via canonicalRoleKey().

HOW TO CHANGE A USER'S ROLE IN SUPABASE
---------------------------------------
Table:  profiles
Column: role  (text)

Recommended: use the exact CANONICAL KEY from Section 1 (e.g. admin, store, superadmin).
Display labels also work (e.g. "Administrator", "Front Desk") — see Section 2.

Example SQL:
  UPDATE profiles SET role = 'admin' WHERE email = 'user@example.com';
  UPDATE profiles SET role = 'store' WHERE email = 'storekeeper@example.com';
  UPDATE profiles SET role = 'superadmin' WHERE email = 'owner@example.com';

SECTION 5 — EXTRA HARD-CODED RULES (not in role bundle alone)
================================================================================

These apply even if a permission appears in a role's list:

bookings:edit, bookings:delete     → admin, superadmin only
reservations:edit                  → admin, superadmin only
rooms:create, rooms:edit, rooms:delete → admin, superadmin only
organizations:edit, organizations:delete → admin, superadmin only
guests:edit, guests:delete           → admin, superadmin, manager
outlet:void                          → admin, superadmin only
outlet:edit, outlet:delete           → admin, superadmin, manager
events:create/edit/delete            → admin, superadmin, manager, front_desk
expenses:*                           → requires expense-menu role (superadmin, admin,
                                       manager, accountant, cashier, auditor)

Special capability helpers (not separate permission keys):
  Kitchen batch create/edit/delete   → admin, superadmin only (canManageKitchenBatchStandards)
  Kitchen / Restaurant sell price    → admin, superadmin, auditor (canEditKitchenBatchSellingPrice)
  Main Bar menu category & price     → admin, superadmin, or auditor (canAuditorEditOutletMenuPricing)
  Restaurant kitchen dish cat/price  → same auditor helper on restaurant department
  Main Bar menu CRUD (full)          → admin, superadmin only (canManageOutletMenu for main_bar)
  F&B Store management               → superadmin, admin, manager, food_beverage
  PO direct approve (skip accountant)→ admin, superadmin, manager


================================================================================
SECTION 6 — PER-USER / PER-ORG OVERRIDES (optional, advanced)
================================================================================

profiles.permission_overrides       JSONB  { "grants": ["perm:key"], "denies": ["perm:key"] }
organizations.role_permission_overrides  JSONB  { "store": { "grants": [...], "denies": [...] } }

Use canonical role keys as object keys in role_permission_overrides.
Permission keys must match Section 3 exactly.
